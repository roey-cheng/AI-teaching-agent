# 会话状态回归 LangGraph：实施与验收计划

状态：本地实现与验收完成（2026-10-25）。范围为本地代码与隔离测试，未迁移现有数据库、未推送或部署。

## 目标与原则

- Deep Agents 创建图，LangGraph State/checkpointer 管理短期会话；不再每轮从业务表重建历史。
- 保留每个已鉴权会话独立缓存图；缓存有上限和闲置回收，回收不删除持久状态。
- 使用现成 `langgraph-checkpoint-mysql` 社区集成（不是 LangChain 官方维护的 MySQL saver），不自行实现 checkpoint 序列化/执行引擎，不引入新的生产数据库。
- 长期画像继续使用 StoreBackend 和经过验证的业务写入工具；会话工作文件与只读技能通过原生 CompositeBackend 分离。
- 权限、额度、消息回执和写入幂等属于业务层，不能因为使用框架而删除。

## 运行和失败语义

1. 后端鉴权产生稳定的 user/session thread_id；客户端不能指定 checkpoint 或其他用户的 thread。
2. 首次使用会话时，完整导入已成功的旧轮次一次（无协议记录的旧消息作为不可信引用，不伪造 reasoning）。之后只提交带稳定消息 ID 的新用户消息。
3. 每个会话在业务数据库保存“已发布 checkpoint_id”。正常发送和失败重试都从该 checkpoint 开始，不盲目读取失败尝试产生的 latest。
4. 图执行完成、同步 checkpoint 写入完成后，将 checkpoint_id 与最终回答放在同一业务事务提交。checkpoint 写入成功但回答事务失败的分支不能污染下轮。
5. 本次保留现有“失败后明确重试整轮”的产品行为，不宣称自动从任意工具中断点继续。checkpoint 保存中间状态，但自动恢复需要单独的产品和副作用策略。
6. 画像工具写入增加按用户问题 ID 的持久回执，与画像变更同事务提交。重试不能重复写，也不能把另一份提案谎称为已保存。

## 实施顺序

- [x] 持久化：接入现成 MySQL saver、生命周期、显式建表流程与启动只读检查。
- [x] 图：显式注入 checkpointer、受限会话缓存、CompositeBackend、按 64K 应用预算配置原生摘要。
- [x] 执行：稳定 thread/message ID、一次性旧历史导入、已发布 checkpoint 指针与回答原子提交。
- [x] 工具：写入持久回执；区分本轮依赖与应保存的会话状态。
- [x] 上下文：准入只检查新问题和固定开销；框架摘要负责长历史；最终请求预算检查继续保留。
- [x] 流式：内部摘要不成为用户回答或“模型思考”；正常回答/工具事件兼容现有前端。
- [x] 迁移与文档：新增向前迁移、不修改旧迁移；说明部署步骤、旧数据导入和回滚边界。
- [x] 验收：离线真实图测试 + 隔离 MySQL 集成测试 + 独立代码复查。

## 验收用例

- 同会话连续两轮，仅传新消息仍保留旧消息，消息不重复；跨用户/会话隔离。
- 重建图、清空图缓存、重开 saver 后仍能恢复已发布会话状态。
- 摘要在应用预算内触发，保存摘要和近期完整工具配对；内部摘要不流向前端。
- 历史归档可写可读，画像/技能路径仍不能任意写入，其他用户命名空间不可访问。
- 工具后失败、取消、checkpoint 成功而业务提交失败、提交确认丢失等不会污染已发布会话。
- 同一问题重试不重复保存画像，冲突提案不会被误报已保存。
- 旧历史只初始化一次；旧记录仍可在聊天界面查看。
- 原有权限、额度、取消、SSE、数据库一致性测试不退化。

## 明确保留的限制

现有单实例数据库运行锁本次不直接删除：它保护现有额度、后台记忆任务和启动清理。多副本/滚动部署需要独立的分布式租约改造，不能假装加上 checkpointer 就已经支持。正式发布依然需要维护窗口和备份。

持久 checkpoint 的保留/清理策略需保护已发布指针及活动分支；本次先保证可恢复和不误删，不自动删除历史 checkpoint。
