# 课件导入器第一阶段实施计划

## 范围

实现离线的 inventory、parse、report 和组合 run 命令。只读取本地 PDF/PPTX，提取原生内容、生成可解释的分流候选与本地报告。本阶段不执行 OCR、视觉 API、Embedding、数据库发布或 Office 转换；这些需求只在报告中列出。禁止 Keynote、桌面自动化以及课件内的代码/链接执行。

## 实施步骤

1. 建立独立 `tools/course_import/` Python 项目与依赖锁；忽略 `data/course_imports/` 派生资料。后端环境、聊天功能和数据库不变。
2. 盘点文件：相对路径、SHA-256、格式、页数、重复内容、加密/损坏/超限/不支持文件。限制文件大小、页数和 PPTX 解压规模；拒绝符号链接。报告不包含设备信息、个人绝对路径或密钥。
3. 原生解析：Docling 关闭 OCR、远程服务和图像描述；PDF 补充文字层/图像/矢量统计；PPTX 用 python-pptx 保留文本框内换行、代码、组合层级、坐标和图片。原文与处理标记分开，保存原始结构，不自动修复代码。
4. 内容分流：原生文字/表格、疑似代码、独立图片候选、组合画面候选、扫描候选、可见性存疑。每项保存触发理由；重复小图只标记装饰候选，不自动丢弃。隐藏页/备注单列，未知或可疑内容进入人工检查。
5. 每份文档独立子进程、超时与失败隔离；内容+解析器版本缓存，原子写入结果与完成标记。重复运行复用完整缓存，损坏缓存重建，不把部分结果当成功。
6. 生成 JSON 清单、逐页 Markdown 和本地 HTML 检查报告。HTML 转义课件内容、禁用脚本和远程资源；页码、元素 ID、文本与图片可以对应。报告明确“解析成功不等于审核通过”，不自动批准发布。
7. 用合成样本测试所有分流、恶意路径/链接、损坏文件、缓存、失败恢复和无外部调用边界；再跑两份 PPTX 与 Template Method PDF，最后处理完整目录。校验源文件哈希不变、派生资料被 Git 忽略。

## 验收

- 三份样本保留代码块边界、页码和图片，存疑文字/组合图明确列出，不凭启发式宣称理解正确。
- 所有支持文件均有成功或失败记录；失败可以重试，未变化的完整结果可以复用。
- 每个候选有理由与来源，人工可以检查；不依赖 Keynote，不调用付费 API，不联网读取文档外链。
- 测试与静态检查通过；提供可运行命令与报告链接。未实现的 OCR/视觉/向量化步骤明确标注。

## 验证结果（2026-10-25）

- 独立环境的依赖锁检查、Ruff 检查/格式检查、20 项自动化测试通过。
- 三份样本 41 页通过后，整批 27 份、652 页完成解析，失败 0。第二次整批运行全部为 `cached`，完整标记、JSON 和图片哈希验证通过。
- 两份 PPTX 的 59 / 35 个非空文本框逐字对照一致（软换行规范化为换行），包括代码文本；18 个原生图片对象保留。白字、孤立字符和越界内容保留并提示审核，不自动删除。
- PDF 核对中发现图片型表格被识别为空表格、原图可能遗漏，已补充原始图像流保留、遗漏图片展示及空表格警告，并加入合成 PDF 回归测试。原始图像流与最终页面显示可能不同，报告明确提示。原始图像对象实例数包括重复徽标/装饰及同图多次引用，不等于教学图数量。
- 页码数量/连续性检查通过；全部源文件 SHA-256 未变；当前结果未包含项目绝对路径；原始资料和派生目录均由 Git 忽略。
- 本地报告：`data/course_imports/phase1/report.html` 与 `report.md`；样本报告位于 `data/course_imports/phase1-samples/`。
- 所有结果仍为 `unreviewed`、`publishable=false`。仅完成提取与候选分流，没有逐页人工审核、OCR、付费视觉调用、向量化、数据库发布或线上部署。
- 本地审核工作台默认只列出 18 个最高优先级页面，支持问题筛选、PDF 页面预览、PPTX 原生结构预览、元素检查、页级/元素级决定以及相同图片批量排除。决定写入独立的 `review-decisions.json`，不修改解析结果；尚未将审核决定接入 enrich 或发布。
