# AI 聊天 Demo：第一版范围与决策

**创建日期：** 2026-09-20

**更新日期：** 2026-09-21

**状态：** 第一版交付范围，尚未实现和验收

本文定义第一版的产品范围：流式 SSE、Deep Agents、长期记忆和失败重试。前期设计草案可在 Git 提交 14c25d5 中查看；当前开发以这三份第一版 Demo 文档为准。

## 1. 交付目标

做一个通过浏览器访问的聊天网站：注册登录、新建和切换会话、逐步显示 AI 回答、保存历史、失败后重试原问题，以及查看和跨会话使用个人记忆。

技术栈是 React + TypeScript、FastAPI、MySQL。Deep Agents 是硬性要求，所有 AI 对话必须实际经过它执行。只部署一个后端进程。

最小演示过程：用户登录 → 聊天并看到 SSE 回复 → 请 Agent 记住中文解释偏好 → Profile Memory 页面出现记录 → 新会话使用该偏好 → 刷新后历史仍在。另需验证一个失败问题能够直接重试。

## 2. 必须保留的功能

| 模块 | 功能 | 第一版行为 |
|---|---|---|
| 账号 | 注册、登录、退出、当前用户 | 邮箱密码，密码哈希；服务端 Session + Cookie；固定 7 天有效 |
| 权限 | 用户隔离 | 后端检查归属，用户只能访问自己的会话、消息和记忆 |
| 会话 | 新建、侧栏、切换 | 左侧栏展示本人全部会话列表；点击一个会话后读取该会话的全部历史消息 |
| 会话 | 默认标题、手动重命名 | 首条消息生成简单标题；手动名称不被覆盖 |
| 聊天 | 文字发送、Deep Agents | 多行输入，禁止空消息，每次通过 Agent 执行 |
| 聊天 | 流式 SSE | 第一版必须逐步显示，不等全部回答生成后才展示 |
| 聊天 | 多轮上下文 | 发给模型的是当前会话最近最多 20 轮成功问答、当前问题和个人记忆；超过模型预算时进一步减少历史，不影响页面查看全部记录 |
| 聊天 | Markdown | 展示段落、列表、代码块，处理不受信任的 HTML |
| 聊天 | 最小并发保护 | 生成期间禁用当前会话发送和重试，后端也原子拒绝第二次新生成 |
| 聊天 | 简单超时与失败提示 | 默认 120 秒请求级 Agent 超时，显示明确错误，保留原问题 |
| 聊天 | 失败重试 | 仅最后一条、已确认失败的问题可以重试；复用原问题，不重复保存 |
| 历史 | 持久化 | 用户消息、已完成回答、最新生成状态保存在 MySQL |
| 历史 | 历史加载 | 页面一次读取当前会话全部消息，不做 cursor 分页；不同时读取其他会话的消息，也不把全部历史自动交给模型 |
| Memory | 提取、保存、跨会话读取 | 明确且适合长期保留的学习目标、编程背景、回答偏好、个人背景和日常偏好，按主题更新 |
| Memory | Profile Memory 页面 | 只查看实际保存的摘要，无手动编辑、删除、开关 |

“失败重试”保留；“成功回答不好，重新生成一个版本”不做。重试复用原 USER，用户主动重新发送同样文字则创建新 USER，两者不能混用。

## 3. 第一版设计与使用边界

| 原方案 | 第一版 |
|---|---|
| 8 张业务表 | 5 张核心表；生成最新状态直接放在 USER 消息上 |
| 11 个业务接口 | 仍为 11 个；PATCH 只保留重命名，失败重试接口保留 |
| 会话及消息 cursor 分页 | 小量演示数据一次读取全部 |
| 归档与恢复相关逻辑 | 暂缓归档，不提供归档参数或入口 |
| 完整尝试记录、队列、领取、180 秒 deadline 与扫描 | 请求内执行，简单运行编号、会话占用和默认 120 秒超时 |
| 断线后后台继续完成 | 检测到断线时取消；回来查询是否已保存结果，不保证继续生成 |
| 重启恢复排队任务和执行状态 | 不恢复执行；核对并清理残留 RUNNING，已完成数据保留 |
| 用户级记忆版本、冲突合并、来源证据计数 | 按用户和主题更新或插入，不覆盖整份 Profile，无证据计数 |
| 多进程部署与共享协调 | 单进程、单实例，旧进程完全退出后才启动新进程 |

第一版保留以下基础保护：后端验证用户权限、数据库唯一约束、成功回复与状态原子保存、同会话单生成，以及保存时检查当前运行编号。

断线不一定意味着失败，可能刚好在回复已提交后断开；页面先查询历史再决定是否允许重试。重启后的残留状态清理只用于避免一直显示“生成中”，不重新调用模型或恢复中途执行。

Memory 不同主题的更新都保留；同主题并发冲突按提交顺序后写生效，暂不保证以用户原陈述时间自动解决矛盾。已保存记忆不因后续聊天失败回滚。

## 4. 五张表及存储职责

| 表 | 保存内容 |
|---|---|
| users | 账号和密码哈希 |
| auth_sessions | 登录凭据哈希、有效期和撤销状态 |
| chat_sessions | 用户归属、标题、手动命名标记、活动时间 |
| messages | 问题、最终回复、每条问题最新生成状态及重试所需运行编号 |
| agent_memory | 按用户和稳定主题保存的记忆摘要 |

不创建独立的 generation_attempts、memory_profiles、memory_evidence。少量最新运行元数据用于失败重试，不表示保存了完整执行历史。

每条 USER 或成功 ASSISTANT 是一条消息。SSE 小片段不各自成为消息；最终回答确认保存后才发送完成事件。失败的半截回答仅在页面临时展示。

MySQL 是历史与记忆的权威存储。无文件上传，因此不启用对象存储。虚拟 /memories/profile.md 由 MySQL 内容投影，不另存一份实际 Markdown 文件。

## 5. Deep Agents 的职责

Deep Agents 运行于后端，组织模型调用、工具执行与记忆使用。后端负责认证、会话归属、历史加载、请求超时和数据库保存，前端负责页面与 SSE 显示。

Agent 配置读取当前用户的虚拟 Profile，并使用我们实现的 save_profile_facts 工具按主题保存明确事实。模型不能自行指定其他用户身份；通用文件写入不能绕过记忆工具。只有真实保存成功才可以确认“已记住”。

聊天历史属于会话，Profile Memory 属于用户并跨会话使用；临时执行状态按本次 attempt_id 隔离。不做执行 checkpoint 的持久化恢复，也不要求实现多个子 Agent。

## 6. 与完整 Coding Lab 的关系

完整架构与数据库文档保留为后续教学系统目标。本 Demo 会话和记忆直接关联 user_id，不使用完整设计中的 Enrollment 与题目外键，不预置课程、Lab、题目或 Enrollment。

Demo 记忆类型以 LEARNING_PREFERENCE、LEARNING_GOAL、PROGRAMMING_BACKGROUND、PERSONAL_BACKGROUND、DAILY_PREFERENCE 为当前范围。[表设计草案第 8 节](2026-09-24-ai-chat-demo-database-design-zh.md#8-agent_memory个人长期记忆)列出 25 个候选主题及个人信息边界；不要求填满，不主动收集敏感信息。本次不新增记忆管理接口；面向真实用户开放前，需另行确认记忆告知、控制与删除方案。具体字段和分类差异以内部设计为准，不声称完整数据库文档原本就是第一版结构。

课程管理、代码编辑器、运行评分、沙箱、课程 RAG、Milvus、文件上传、联网搜索和教师 Dashboard 都不在此次交付中。

## 7. 开发顺序和学习方式

按要求推进：

1. 阶段 0：理解当前 Plan，准备环境和空项目，验证前后端、MySQL 服务和最小模型调用。
2. 建数据库：项目数据库与应用连接账号。
3. 建表设计：明确 5 张表的字段、关系、索引和约束。
4. Schema 层：ORM 表模型与请求响应数据模型。
5. Migration：检查并执行迁移，真正创建业务表。
6. 业务逻辑层：账号、会话、聊天、Agent、Memory、超时和重试。
7. 接口层：接入 11 个业务接口及 SSE。
8. 页面联调、错误场景、演示和部署连通验证。

“先建表”先完成结构设计，实际创建交给 Migration，避免手工和迁移重复建表。每一阶段先看当日计划，理解后分块实现、运行验证，不清楚的地方及时问。阶段 0 的 /health 和空页面用于环境检查。

保留重试后需要安排额外状态与重复请求测试；不能因为接口复用就认为没有工作量。第 4 天前争取做出可用网页，第 5 天留给联调、演示和修复，别把 Agent、SSE、Memory 的第一次验证都留到最后。

## 8. 演示验收

1. A 注册登录，直接进入聊天，无需加入课程。
2. 新建会话，看到 Deep Agents 回答通过 SSE 逐步显示。
3. 连续追问，验证多轮上下文。
4. 告诉 Agent：“我是 Python 初学者，喜欢中文解释，请记住。”
5. 打开 Profile Memory，检查实际保存的摘要；新会话验证使用。
6. 切换、重命名会话，确认侧栏和历史正常。
7. 刷新、退出重登、重启后端，确认已完成历史与记忆保留。
8. 用 B 登录并直接请求 A 的资源，确认后端隔离。
9. 模拟模型失败或超时；原问题保留，点击重试后 SSE 返回新回答，不重复保存问题。
10. 双击发送、重复重试请求不能启动两个生成；成功消息或旧失败问题不能重试。
11. 流中断后查询历史确认结果；部分回答不能伪装成成功落库。
12. 旧问题失败、新问题成功、刷新后，旧问题仍显示失败且不能再重试。
